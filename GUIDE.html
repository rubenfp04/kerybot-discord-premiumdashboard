kerybot Setup Guide

A step-by-step guide to install, configure, and run your kerybot instance with the full web dashboard.

v1.0.0 — Node.js + Discord.js v14

📋 Requirements

Make sure you have the following installed before starting.

Software Version Notes
Node.js 18+ LTS recommended. Download from nodejs.org
MongoDB 6+ Local install or MongoDB Atlas (free tier works)
Git Any To clone the repository
Stripe CLI Optional Only needed for testing premium payments locally
💡
On Windows, you can install Node.js and MongoDB via winget:
winget install OpenJS.NodeJS.LTS and winget install MongoDB.Server

📦 Installation

Clone the repository and install all dependencies.

1

Clone the repository

git clone https://github.com/kerybot/kerybot-discord-dashboard.git
cd kerybot-discord-dashboard
2

Install dependencies

npm install
📦
This installs discord.js, express, mongoose, passport, canvas, stripe, and all other packages automatically.
3

Verify installation

node -e "require('discord.js'); console.log('OK')"

If you see OK, all core dependencies are installed correctly.

🤖 Discord Application Setup

Create a Discord application and configure OAuth2 for the dashboard.

1

Create the application

Go to Discord Developer Portal → New Application → give it a name → Create.

2

Create the bot

Go to Bot tab → Add Bot → Copy the Token (you'll need it for .env).

🔒
Never share your bot token. If it gets leaked, immediately reset it from the Developer Portal.
3

Enable required intents

In the Bot tab, scroll down and enable:

  • Presence Intent
  • Server Members Intent
  • Message Content Intent
4

Configure OAuth2

Go to OAuth2 → General:

  • Copy Client ID and Client Secret
  • Add redirect URL: http://localhost:3000/auth/callback
5

Invite the bot

Go to OAuth2 → URL Generator:

  • Scopes: bot, applications.commands
  • Permissions: Administrator (or select specific ones)
  • Copy the generated URL and open it in your browser

⚙️ Environment Configuration

Create a .env file in the project root with your credentials.

1

Create the .env file

# Discord
BOT_TOKEN=your_bot_token_here
CLIENT_ID=your_client_id_here
CLIENT_SECRET=your_client_secret_here

# MongoDB
MONGO_URI=mongodb://localhost:27017/kerybot

# Dashboard
DASHBOARD_PORT=3000
CALLBACK_URL=http://localhost:3000/auth/callback
SESSION_SECRET=any_random_string_here

# Bot Owner
OWNER_ID=your_discord_user_id

# Stripe (optional — for premium features)
STRIPE_SECRET_KEY=sk_test_XXXX
STRIPE_WEBHOOK_SECRET=whsec_XXXX
Variable Where to find it
BOT_TOKENDeveloper Portal → Bot → Token
CLIENT_IDDeveloper Portal → OAuth2 → Client ID
CLIENT_SECRETDeveloper Portal → OAuth2 → Client Secret → Reset
OWNER_IDDiscord → Settings → Advanced → Enable Developer Mode → Right-click your profile → Copy ID
SESSION_SECRETAny random string (e.g., generate with node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
⚠️
The .env file is included in .gitignore. Never commit it to version control.

🗄️ Database Setup

kerybot uses MongoDB to store guild settings, warnings, and user levels.

A

Option A: Local MongoDB

If MongoDB is installed locally, make sure the service is running:

# Windows (run as admin)
net start MongoDB

# macOS / Linux
sudo systemctl start mongod

Your MONGO_URI will be: mongodb://localhost:27017/kerybot

B

Option B: MongoDB Atlas (Cloud)

  1. Go to MongoDB Atlas and create a free account
  2. Create a cluster (free M0 tier is enough)
  3. Create a database user with a password
  4. Whitelist your IP (or use 0.0.0.0/0 for any IP)
  5. Click Connect → Connect your application → Copy the URI
MONGO_URI=mongodb+srv://username:password@cluster.xxxxx.mongodb.net/kerybot

🚀 First Run

Register the slash commands and start the bot.

1

Register slash commands

This only needs to be done once (or whenever you add/modify commands):

node src/bot/deploy-commands.js

You should see: Registering X slash commands... followed by Commands registered successfully.

2

Start the bot

node index.js

You should see the ASCII banner, system info, database connection, and "Bot Online" section in the console.

3

Open the dashboard

Open http://localhost:3000 in your browser. Click "Get Started" to log in with Discord.

✅
If you see the landing page with your bot's stats and can log in — congratulations! Your kerybot instance is running.

🧩 Available Plugins

Each plugin can be enabled/disabled per guild from the dashboard. Here's what each one does:

👋 Welcome

Custom welcome messages, canvas cards, DMs to new members.

🚪 Farewell

Send a message when a member leaves the server.

🛡️ Moderation

Ban, kick, warn, clear commands + automod rules (badwords, spam, caps, etc.).

📋 Logs

Log moderation actions to a designated channel.

🎭 Autorole

Automatically assign a role to new members on join.

🎟️ Tickets

Support ticket system with panels, categories, close messages.

💡 Suggestions

Community suggestions with upvote/downvote and approval channels.

🎯 Reaction Roles

Assign roles when users react to a message with a specific emoji.

📊 Levels PREMIUM

XP system with rank cards, multiplier, level-up announcements.

⭐ Starboard PREMIUM

Highlight popular messages when they receive enough star reactions.

🌐 Language Configuration

kerybot supports English and Spanish for both the dashboard and the bot.

🖥️

Dashboard Language

Users can switch languages using the EN / ES buttons in the top navigation bar. The preference is saved as a cookie for 1 year.

You can also set the language via URL parameter: ?lang=en or ?lang=es

🤖

Bot Language (per guild)

Each guild can set its own language from the dashboard settings. Bot responses (embeds, error messages, level-up announcements, etc.) will be in the configured language.

Default language: es (Spanish). Can be changed to en (English) from the dashboard.

📁

Locale Files

Translation files are JSON files in the locales/ directories:

src/dashboard/locales/
  ├── en.json ← Dashboard English
  └── es.json ← Dashboard Spanish

src/bot/locales/
  ├── en.json ← Bot English
  └── es.json ← Bot Spanish

💎 Premium & Stripe Setup

Premium features (Levels, Starboard) are gated behind Stripe payments. The bot auto-creates products and prices on startup.

1

Create a Stripe account

Go to Stripe Dashboard and create a free account. You can use test mode for development.

2

Get your API keys

Go to Developers → API keys. Copy the Secret key (starts with sk_test_) and add it to .env as STRIPE_SECRET_KEY.

3

Set up webhook (local dev)

Install the Stripe CLI and forward webhooks:

stripe listen --forward-to localhost:3000/stripe/webhook

Copy the whsec_... secret shown and add it to .env as STRIPE_WEBHOOK_SECRET.

4

Auto-created plans

When the bot starts, it automatically creates a "kerybot Premium" product with three price tiers:

Plan Price Type
Lifetime€19.99One-time
Yearly€9.99/yrRecurring
Monthly€1.99/moRecurring
💡
If you don't set STRIPE_SECRET_KEY or leave it as sk_test_XXXX, Stripe is disabled. The bot works fine — premium plugins just stay locked.

🔧 Troubleshooting

Common issues and how to fix them.

!

Bot won't start — "TOKEN_INVALID"

Your BOT_TOKEN in .env is wrong or expired. Go to the Developer Portal → Bot → Reset Token and update the value.

!

Dashboard login redirects to home

Check that CALLBACK_URL in .env matches exactly what's in the Developer Portal → OAuth2 → Redirects. Including the protocol and port.

!

Commands not showing in Discord

Run node src/bot/deploy-commands.js again. Global commands can take up to 1 hour to propagate. For instant testing, use guild-specific commands.

!

Canvas errors on npm install

The canvas package requires build tools. On Windows: npm install --global windows-build-tools. On Linux: sudo apt-get install build-essential libcairo2-dev libjpeg-dev libpango1.0-dev libgif-dev

!

MongoDB connection refused

Make sure MongoDB is running. On Windows: net start MongoDB. Or use MongoDB Atlas (cloud) — see the Database section above.

!

Stripe webhook not activating premium

Make sure the Stripe CLI is forwarding to the correct URL: stripe listen --forward-to localhost:3000/stripe/webhook. Also verify STRIPE_WEBHOOK_SECRET in .env matches the CLI output.
